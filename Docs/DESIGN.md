# 设计原则

改 UI 前先读这一页。具体的取舍记录在 [`DECISIONS.md`](DECISIONS.md)，颜色、字号、圆角等令牌在 `Sources/Bandwagon/Views/DesignSystem/Theme.swift`。

### 使用者
个人运维者，在日常工作或夜间排查时使用 Bandwagon 管理自己的 VPS、搬瓦工套餐流量和 3X-UI 节点。核心任务是快速回答三个问题：服务器是否健康、流量是否会超额、哪个客户端需要处理。用户希望少配置、少跳转，打开后能在几秒内得到可信判断。

### 品牌气质
可靠、清晰、克制。界面应传达稳定、可控、低打扰的桌面工具感；告警要明确但不制造焦虑，数据要精确但不过度堆叠。

### 视觉方向
浅色优先，同时支持深色主题。参考 macOS 原生工具的层级、留白、控件反馈和可读性；采用安静的中性底色、单一蓝色主行动色和少量语义状态色。明确避免信息过密、霓虹科技感、发光渐变、无意义装饰和“所有内容都做成卡片”的视觉噪音。

### 五条原则
1. 先给结论，再给证据：首屏首先展示健康状态、流量余量和需要注意的对象。
2. 一屏一任务：总览用于判断，详情页用于分析，设置页用于连接，不把所有信息塞进同一屏。
3. 状态必须可扫描：使用文字、图标、位置和颜色共同表达状态，不依赖单一颜色。
4. 渐进式披露：常用动作直接可见，高级诊断数据通过详情和展开进入。
5. 安静但不隐形：动效只用于刷新、状态变化和反馈；支持减少动态效果，并保证键盘可操作。

### 无障碍基线
- 以 WCAG 2.2 AA 为基线，正文与背景至少 4.5:1 对比度，大字号至少 3:1；深浅两套配色都要满足。
- 主要流程键盘可完成：⌘R 刷新、⌘S 保存设置、Tab 能走到每个控件，表头排序与行操作都有可聚焦的按钮。
- 重要状态同时用文字和图标 / 位置表达，不只靠颜色；重复出现的按钮带上对象名（如「复制 某某 的邮箱」），VoiceOver 才分得清。
- 遵守系统「减少动态效果」（`accessibilityReduceMotion`）：只保留淡入淡出，去掉位移和弹簧动画。
- 图标按钮的可点区域不小于 22pt，宽窗口下关键列不被挤出视野。
